## App.tsx routing hierarchy (priority order)
1. `isLoading` → `<LoadingScreen />`
2. `!isAuthenticated` → `<SignInScreen />`
3. `activeModule !== null` → module wrapper with back bar
4. `activeConversation !== null` → `<ConversationView conversationId={...} onBack={...} />`
5. Default → `<WorkspaceHome />`

**Why:** WorkspaceHome replaces RaiDashboard as the default landing. Conversations get their own view. Modules (LogicGate, RFP, Development) remain accessible via `onSelectModule` callback passed down from WorkspaceHome.

## State types
```typescript
type ModuleId = string | null
interface ConversationRef { id: string; title: string; activeLens?: string | null; [key: string]: unknown }

const [activeModule, setActiveModule] = useState<ModuleId>(null)
const [activeConversation, setActiveConversation] = useState<ConversationRef | null>(null)
```

## WorkspaceHome props
```
user, isAdmin, onLogout, onSelectModule, onOpenConversation
```
`onOpenConversation` receives a `ConversationRef` (the full row from the API) and sets `activeConversation`.

## ConversationView props
```
conversationId: string, onBack: () => void
```
Fetches full conversation and messages via generated React Query hooks. Streams assistant responses via direct `fetch` (not via generated hooks — SSE is not supported by Orval/React Query mutation pattern).

## Frontend hook naming (generated by Orval)
- `useListConversations()` — GET /conversations
- `useCreateConversation()` — POST /conversations
- `useGetConversation(id)` — GET /conversations/:id
- `useChangeConversationLens()` — PUT /conversations/:id/lens
- `useListMessages(id)` — GET /conversations/:id/messages
- Streaming is via raw `fetch`, not a generated hook

## ConversationView SSE field mapping
The API response uses snake_case (generated from OpenAPI):
- `conv.active_lens` (not `conv.activeLens`)
- `conv.opportunity_id` (not `conv.opportunityId`)
- `conv.title` — same
