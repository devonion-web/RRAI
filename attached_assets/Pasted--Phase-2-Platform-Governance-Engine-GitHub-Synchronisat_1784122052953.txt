# Phase 2 — Platform Governance Engine
## GitHub Synchronisation & Platform Status Engine

You are implementing a permanent platform capability.

This is NOT a one-off report.

This becomes a core RRAI engine responsible for ensuring that the implementation, repository and architecture remain synchronised forever.

The platform now has three environments:

• GitHub (authoritative repository)
• Replit (implementation/runtime)
• Claude Project (architecture and governed knowledge)

GitHub is the single source of truth.

Replit is connected directly to GitHub.

Claude consumes the repository as its architectural knowledge source.

The objective of this engine is to ensure that Claude never works from an outdated understanding of the platform again.

This engine must become part of the permanent platform architecture.

--------------------------------------------------
OBJECTIVES
--------------------------------------------------

Build a Platform Governance & Synchronisation Engine that can:

• Inspect the repository
• Understand the current implementation
• Compare implementation against architecture
• Detect implementation drift
• Generate authoritative implementation documents
• Maintain implementation history
• Provide Claude with an accurate snapshot of the platform

These documents are generated from the repository and implementation.

They are NOT manually maintained.
